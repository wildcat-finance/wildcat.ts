# SDK 3.2.10-beta

This release aligns the Sepolia SDK with protocol V2.5.4 and subgraph V2.5.12.
It branches from `release/v3.2` at `bfb122725f84a2505c8214b29fbf123d38e9432e`.
The subgraph reference is `release/v2.5` at
`584e5de1c22a2c8cc3b79aeda707392392d9be83`.

SDK 3.2.9-beta already selected subgraph V2.5.12, but retained the V2.5.3
transaction targets and lens. The Sepolia addresses now are:

| SDK deployment | V2.5.4 address |

| `HooksFactoryStandard` | `0x5ae696F4F1A771799e8d03Dc232C8F843f44417f` |
| `HooksFactoryRevolving` | `0x01c3E16434eCd4c76e2ff3a88D1e6Bf82BBda07e` |

| `MarketLensV2_5` | `0x204BAe0AE3De919a88812065866Dd03b097BC6A7` |

The protocol's [wrapper access fix](https://github.com/wildcat-finance/v2-protocol/pull/165)
allows transfers to a market's registered wrapper without approving it as an
ordinary lender. The fixed hook templates are deployed on Sepolia. Retired
wrappers remain discoverable, including their indexed balances and history;
their factories are excluded from new wrapper deployment. Existing affected
wrappers cannot be repaired by this SDK update.

Two additional SDK omissions are fixed:

- Market detail, list, and snapshot fragments now select `totalAssets`.
  `Market.fromSubgraphMarketData()` uses snapshot liquidity when available,
  otherwise root market liquidity. Previously it always reported zero.
  `IndexedMarketSnapshot.totalAssets` exposes the indexed value as `bigint`.
  Indexed state still needs live hydration before transaction decisions.
- `Market.scaleAmount()` rounds down for the V2.5 event family, matching
  transfers and withdrawal requests. Deployment labels such as `v2.5.4` do
  not select arithmetic. Legacy families retain half-up rounding. The new
  `rayDivDownBigint()` helper checks unsigned operands, overflow, and division
  by zero; existing generic division helpers retain their semantics.

Subgraph V2.5.12 adds no GraphQL fields or types. The SDK already preserves its
block-final `timeDelinquent` and `EVENT_AND_CONTRACT_CALL` snapshot provenance.
For V2.5, `MarketInterestAccrual.timeWithPenalties` means seconds actually
charged a delinquency fee, including zero at a zero fee rate. It is not a
replacement for the stored delinquency clock. Legacy analytics retain their
projected exposure meaning. These distinctions now have regression coverage
and public type documentation.

Validation on 2026-09-08:

- `npm run build` passed; `npm run mocha -- --reporter dot` passed 693 tests.
- Changed TypeScript files passed ESLint. A local npm tarball passed import,
  deployment configuration, arithmetic, fragment, and declaration checks.
- All 81 SDK GraphQL operations validate against the live V2.5.12 schema,
  which matches the checked-in schema. Compatible function argument and return
  encodings match the V2.5.4 protocol artifacts; legacy ABI entries are retained.
- Live SDK reads found no factory target mismatches. All six current
  factory/template pairs pass SDK deployment authority checks.
- The default indexed market list returned 482 markets, including 227 with
  nonzero liquidity. Market detail and interest-accrual queries also succeeded
  through the gateway.
- All 29 historical wrappers remained discoverable through the live SDK
  subgraph path. A V2.5.3 wrapper's account and history remained readable while
  its deployment capability returned `UnsupportedFactory`.
- The new lens and its three helpers match the protocol deployment artifacts
  after masking constructor immutables. SDK market and borrower hooks reads
  through the new lens succeeded.

The observed indexer reported no indexing errors and configuration digest
`969c3d4d7fa55a165197b1a47d4aa3f500b54f278b989cc1267926eee71ec4ff`.
The underlying indexer's schema introspection was used because the public
gateway rejects full introspection at its query-depth limit; SDK application
queries were checked through the public gateway.
