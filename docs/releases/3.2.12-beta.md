# SDK 3.2.12-beta

Historical Sepolia V2.5 preview markets can now hydrate through the configured
V2.5 lens even when they predate the borrower identity getters. Single-market,
batch, account, and refresh reads share the same recovery path.

At Sepolia block `11699651`, market
`0x00e01c5d6ea5ba136f24acce0399b1a6119d4bb0` reports version `2.5`, but
`borrowerPrincipal()` reverts. The V2.5 lens's unified read calls that getter
after successfully reading the base market data. SDK 3.2.11-beta then switches
to the older V2 lens, which reports its periodic hooks as kind `0` and causes
`Unknown hooks kind: PeriodicTermHooks, version #0`.

The SDK now tries the configured lens's base `getMarketData` and compact
`getMarketsLiveDataV2` reads. Both must succeed. The compact data preserves the
revolving fields and their accrued state: this market has a 400 bps commitment
fee and a present, zero drawn amount. Its periodic withdrawal configuration
also survives hydration. Previously the account fallback succeeded but
incorrectly classified it as standard.

Successful unified batch reads still use one request. Failed batches recover
sequentially per market, preserving order and modern markets' identity metadata.
Recovery costs additional requests; it never omits failed markets. Chains
configured for the older V2 lens continue to use it. When V2.5 is configured,
failure no longer downgrades V2 reads to that older, incompatible hook schema.
Generic readers retain their V1 fallback.

Missing identity fields remain undefined and a freshly hydrated compatibility
market's `eventGeneration` remains `unknown`. Refreshes retain existing indexed
identity and event-generation metadata. Successful hydration does not establish
support for every transaction or event convention of a preview deployment;
the SDK does not infer those from the market's `version()` string.

`MarketReadError` is exported for failed recovery. Its `cause` retains the
original read error and `fallbackError` retains the recovery error; batch and
generic V1 recovery can nest these errors. Identity mismatches still fail
immediately. Unsupported hooks and failed compact reads do not yield partially
hydrated models.

The offline regression fixture records the reported market and block. To repeat
the read-only RPC check with an archive-capable Sepolia endpoint, set
`PTH_RPC_URL` in the environment and run:

```sh
npx mocha --no-config --require ts-node/register --timeout 180000 \
  test/read/historical-market.spec.ts --grep 'against the pinned Sepolia block'
```

The live check verifies the chain and block hash before checking single, batch,
and account hydration. It does not submit transactions.
