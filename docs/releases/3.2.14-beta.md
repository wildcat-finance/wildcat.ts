# SDK 3.2.14-beta

Supports Sepolia protocol v2.5.6 and subgraph v2.5.14. Prepared on
2026-10-04 on `release/v3.2.14-beta`, based on `feat/v2.5.5-sdk` at
`9c79b05dd6896d82f32641c8e3a688483b2cb08c` (package `3.2.13-beta`).

## Routing and hook behavior

The Sepolia default endpoint is now
`https://graph.wildcat.finance/sepolia/v2.5.14`. The gateway route passed the SDK's
anonymous read checks on 2026-10-04. Callers can select
`https://graph.hinterlight.net/sepolia/v2.5.14` explicitly for provider checks.
Endpoint selection does not establish deployment health or indexing completion.

Protocol v2.5.6 replaces only the three built-in hook templates. The SDK retains
the v2.5.5 factory, lens, wrapper and AccessList addresses adopted in
[3.2.13-beta](./3.2.13-beta.md). Other chains and historical read routing are
unchanged. New hook instances are discovered through enabled template
registrations on the retained standard/revolving factories.

All three new templates freeze maximum supply and minimum deposit from a
nonzero repayment date. Fixed-term hooks also freeze maturity changes, and
periodic-term hooks reject new APR-reduction proposals. These preview APIs now
return their respective `MarketInRepayment` status for the affected operations:

- `previewSetMaxTotalSupply`
- `previewSetMinimumDeposit`, including setting the minimum to zero
- `previewSetFixedTermEndTime`
- `previewProposeAnnualInterestBips`

Their existing transaction preparation/submission paths enforce these previews.
The new maximum-supply callback is a required hook flag, merged by the protocol
during market creation; SDK deployment argument encoding stays unchanged.

`Market.hooksTemplateAddress` preserves implementation identity from indexed
and full lens reads, including legacy reads. Compact refreshes retain it; full
refreshes reject a different template identity before changing the model.
`Market.hasFrozenHookParameters` combines the known v2.5.6 template identity with
`hasReachedRepaymentDate`, using the model's observed timestamp. The freeze
remains active after closure. Refresh before deciding whether to transact.

`supportsRepaymentParameterFreeze(chainId, hooksTemplateAddress)` recognizes
the three deployed Sepolia templates, independent of address casing. Factory
generation labels cannot distinguish these implementations: both old and new
hooks use the same factories. Existing instances of older templates retain
their previous behavior. Unknown identities and other chains do not acquire
the new restriction merely from a repayment date or a callback flag. A false
result does not establish that an arbitrary custom hook permits the action.

No function/event tuple, GraphQL schema, or generated query change is required
by this protocol/subgraph update. Regenerating the existing bindings and queries
produced identical outputs. The new hook error has the existing
`MarketInRepayment()` selector already included in `wildcatMarketV2_5Abi`.

## Local verification

- Production TypeScript build and changed-file ESLint passed.
- Full offline Mocha suite: 756 passing, one optional live test skipped.
- Code generation passed; 375 factory/market/lens ABI entries match the finalized
  protocol deploy-profile artifacts.
- Tests cover all six standard/revolving × open/fixed/periodic combinations,
  immediately before/at/after repayment, closure, unscheduled markets, older
  hook instances, transaction rejection, and indexed/full/compact hydration.
- SDK deployment targets and new template identities match the finalized
  handoff and subgraph descriptor. Existing deployment constants, other-chain
  URLs, generated ABIs, GraphQL output, and dependency lockfile are unchanged.

Reproduce the local checks with dependencies installed:

```sh
yarn codegen
node scripts/check-v2.5-protocol-abis.js ../v2-protocol/deploy-out
yarn build
env -u PTH_RPC_URL yarn mocha
```

## Synced endpoint and fork verification

Final checks against synced Hinterlight, Goldsky, and the gateway completed on
2026-10-04. Both direct providers passed metadata validation and validation of
all 82 SDK query documents. Factory/registration discovery and indexed market
data agreed at Sepolia block 11843159, including the six new registrations,
their receipt-backed initcode commitments, and six predecessor disables. The
SDK's default gateway endpoint returned the same data at that block. Its public
depth limit rejects the standard introspection query; the SDK read paths tested
through it passed without credentials.

Indexed hydration covered all 484 markets; compact and full RPC refreshes
covered 20 representatives across market, hook, and factory generations. The
optional historical-market archive test also passed. No new-template hook
instances existed in the indexed data at the checked block, so new-template
execution was checked separately on a local fork.

`scripts/verify-v2.5.6-fork.js` exercises all six enabled hook/factory combinations:
SDK deployment, the required maximum-supply callback, parameter previews and
contract reverts at repayment, default, automatic closure, and recovery. The
freeze stays active after closure. The market's existing
`CapacityChangeOnClosedMarket` error precedes the maximum-supply hook at closure;
minimum-deposit changes still revert with `MarketInRepayment`. All six cases
passed against a fork of Sepolia block 11843157; the snapshot was restored.

Reproduce the fork check with `yarn build` complete, using two terminals:

```sh
anvil --host 127.0.0.1 --port 8545 --chain-id 11155111 \
  --fork-url https://eth-sep.hinterlight.net --fork-block-number 11843157
# In the other terminal, from the SDK repository:
V2_5_FORK_RPC_URL=http://127.0.0.1:8545 node scripts/verify-v2.5.6-fork.js
```

The script requires a loopback Anvil endpoint and reverts its local writes. The
older `verify-v2.5.5-fork.js` remains pinned to its original release scenario.
